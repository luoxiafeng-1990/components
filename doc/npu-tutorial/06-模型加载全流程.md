# 6. 模型加载全流程 —— 从文件到硬件推理的 7 步 API 调用

> 本文基于 `NpuInferenceConsumer.cpp`（1,250 行）的实际代码，
> 逐步解析模型从 .nb 文件加载到 NPU 硬件执行推理的完整流程。

---

## 一、整体调用链路

```
qa_cases 命令行
    │
    ├─ NpuPlugin::applyCliToConfig() → 配置模型路径、核心索引等
    │
    ├─ NpuInferenceConsumer::initialize()
    │   └─ loadModel()
    │       ├─ [1] ta_runtime_init()
    │       ├─ [2] ta_runtime_load_model_from_file()
    │       ├─ [3] ta_runtime_query() × 3（IO 数量、输入属性、输出属性）
    │       ├─ [4] posix_memalign() + ta_runtime_set_input_cva()
    │       └─ [5] ta_runtime_create_buffer() + ta_runtime_set_output()
    │
    ├─ NpuInferenceConsumer::consume() [每帧重复]
    │   ├─ preprocessVirtualAddr() 或 preprocessPhysicalAddr()
    │   ├─ [6] runInference()
    │   │   ├─ ta_runtime_run_network()
    │   │   └─ ta_runtime_invalidate_buffer()
    │   └─ postprocess()
    │
    └─ NpuInferenceConsumer::finalize()
        └─ releaseModel()
            ├─ [7] ta_runtime_destroy_buffer()
            ├─ ta_runtime_destroy_context()
            └─ ta_runtime_deinit()
```

## 二、步骤 1：ta_runtime_init() —— 驱动初始化

**源码位置**: `NpuInferenceConsumer.cpp` 第 229 行

```c++
bool NpuInferenceConsumer::loadModel() {
    int status = ta_runtime_init();
    if (status != 0) {
        LOG4CPLUS_ERROR_FMT(logger(), "ta_runtime_init failed: 0x%x", status);
        return false;
    }
```

**驱动内部发生的事（vip_drv_interface.c do_init() 第 83 行起）**：

```c
static vip_status_e do_init(void* data) {
    // 1. 版本检查：确保用户空间库与内核模块版本一致
    if (init_data->version != ((VERSION_MAJOR << 16) | ...)) {
        return VIP_ERROR_NOT_SUPPORTED;
    }
    
    // 2. 40位地址检查
    if ((sizeof(vip_address_t) <= 4) || (sizeof(vip_virtual_t) <= 4)) {
        return VIP_ERROR_NOT_SUPPORTED;
    }
    
    // 3. 创建/获取全局上下文互斥锁
    mutex_lock(&kinit_mutex);
    
    // 4. 如果是第一个进程初始化：
    //    - 查询硬件信息（PID 匹配 vip_chip_info[]）
    //    - 初始化 MMU 页表
    //    - 初始化任务调度器
    //    - 初始化电源管理
    //    - 创建 daemon 线程和 core 等待线程
    
    // 5. 如果已初始化：
    //    - 增加引用计数
    //    - 注册新进程 ID
}
```

## 三、步骤 2：ta_runtime_load_model_from_file() —— 加载 .nb 模型

**源码位置**: 第 235-241 行

```c++
status = ta_runtime_load_model_from_file(
    &nnrt_context_,           // 输出: 网络上下文句柄
    config_.model_path.c_str(), // .nb 文件路径（如 "/usr/data/npu/resnet50/network_binary.nb"）
    config_.npu_core_index    // NPU 核心索引（0 或 1）
);
```

**驱动内部流程**：

```
ta_runtime_load_model_from_file()
    │
    ├─ 读取 .nb 文件到内存
    │   - fopen() → fread() → fclose()
    │   - NBG 文件包含: 网络图、权重系数、命令序列、I/O 描述
    │
    ├─ vip_create_network() [内核态]
    │   ├─ 解析 NBG 格式头（Magic='VPMN'、版本、目标芯片）
    │   ├─ 验证目标芯片与当前硬件是否兼容
    │   ├─ 解析所有 Section（NN_INSTR、PPU_INSTR、COEF_DATA 等）
    │   └─ 创建网络对象
    │
    ├─ vip_prepare_network() [内核态]
    │   ├─ 分配视频内存存储权重系数（COEF_DATA）
    │   ├─ 分配命令缓冲区存储 NN 指令（NN_INSTR）
    │   ├─ 填充 MMU 页表映射
    │   ├─ 翻译 NBG 中的 LoadState 命令
    │   ├─ 应用 Patch 修正（重定位地址）
    │   └─ 如果 vpmdPRELOAD_COEFF >= 2: 准备权重预加载到 VIP SRAM
    │
    └─ 返回 nnrt_context_ 句柄
```

## 四、步骤 3：ta_runtime_query() —— 查询模型 I/O 信息

**源码位置**: 第 243-319 行

```c++
// 3a. 查询输入/输出数量
taconn_input_output_num_t num{};
ta_runtime_query(&nnrt_context_, TACONN_QUERY_IN_OUT_NUM, &num);
input_num_  = num.input_num;    // 通常 = 1（一张图片）
output_num_ = num.output_num;   // ResNet50 = 1, YOLOv5 = 3

// 3b. 查询输入属性
for (int i = 0; i < input_num_; i++) {
    taconn_inout_attr_t attr{};
    attr.index = i;
    ta_runtime_query(&nnrt_context_, TACONN_QUERY_INPUT_ATTR, &attr);
    input_attrs_.push_back(attr);
    
    // 日志输出示例：
    // Input[0]: dims=[640,640,3,1], format=INT8, quant=AFFINE
}

// 3c. 查询输出属性
for (int i = 0; i < output_num_; i++) {
    taconn_inout_attr_t attr{};
    attr.index = i;
    ta_runtime_query(&nnrt_context_, TACONN_QUERY_OUTPUT_ATTR, &attr);
    output_attrs_.push_back(attr);
    
    // 日志输出示例：
    // Output[0]: dims=[80,80,255,1], format=INT8, quant=AFFINE
}
```

**输入维度解析**（第 267-304 行）：

代码需要从 4D 张量中识别出 H×W，因为不同模型的维度排列不同：

```c++
if (d2 == 3u && d3 == 1u && d0 >= 16u && d1 >= 16u) {
    // [H, W, C, N] 格式，如 YOLO [640,640,3,1]
    model_input_h_ = d0;  // 640
    model_input_w_ = d1;  // 640
} else if (d0 == 3u && d3 == 1u && d1 >= 16u && d2 >= 16u) {
    // [C, H, W, N] 格式
} else if (d1 == 3u && d2 >= 16u && d3 >= 16u) {
    // [N, C, H, W] 格式
} else if (d3 == 3u && d1 >= 16u && d2 >= 16u && d0 <= 16u) {
    // [N, H, W, C] 格式
}
```

## 五、步骤 4：分配输入缓冲区

**源码位置**: 第 373-396 行

```c++
// 分配输入 tensor 数组
input_tensors_ = (taconn_input_t*)malloc(sizeof(taconn_input_t) * input_num_);

for (int i = 0; i < input_num_; i++) {
    auto fmt = static_cast<taconn_data_format_t>(input_attrs_[i].data_format);
    size_t buf_size = calcBufferSize(fmt, getElementNum(input_attrs_[i]));
    
    input_tensors_[i].index = i;
    input_tensors_[i].size  = buf_size;
    input_tensors_[i].data  = nullptr;
    
    // 256 字节对齐分配（NPU DMA 要求对齐）
    posix_memalign(&input_tensors_[i].data, 256, buf_size);
    memset(input_tensors_[i].data, 0, buf_size);
}

// 将 CPU 虚拟地址缓冲区绑定到网络输入
status = ta_runtime_set_input_cva(&nnrt_context_, input_num_, input_tensors_);
```

**对于 YOLOv5 640×640 INT8 模型**：
```
buf_size = 640 × 640 × 3 × sizeof(int8_t) = 1,228,800 字节 ≈ 1.2 MB
对齐到 256 字节边界
```

## 六、步骤 5：分配输出缓冲区

**源码位置**: 第 398-417 行

```c++
// 分配输出 buffer 数组
output_buffers_ = (taconn_buffer_t*)malloc(sizeof(taconn_buffer_t) * output_num_);

for (int i = 0; i < output_num_; i++) {
    auto fmt = static_cast<taconn_data_format_t>(output_attrs_[i].data_format);
    size_t buf_size = calcBufferSize(fmt, getElementNum(output_attrs_[i]));
    
    // 由驱动创建 DMA 可访问的缓冲区
    status = ta_runtime_create_buffer(&nnrt_context_, buf_size, &output_buffers_[i]);
}

// 绑定输出缓冲区
status = ta_runtime_set_output(&nnrt_context_, output_num_, output_buffers_);
```

**注意区别**：
- 输入缓冲区用 `posix_memalign()` 在用户空间分配，通过 `ta_runtime_set_input_cva()` 注册
- 输出缓冲区用 `ta_runtime_create_buffer()` 由驱动分配 DMA 内存

## 七、步骤 6：推理执行

**源码位置**: 第 560-574 行

```c++
bool NpuInferenceConsumer::runInference() {
    int status = ta_runtime_run_network(&nnrt_context_);
    if (status != 0) {
        LOG4CPLUS_ERROR_FMT(logger(), "ta_runtime_run_network failed: 0x%x", status);
        return false;
    }
    
    // 使输出缓冲区的 CPU 缓存失效，确保读到 NPU 写入的最新数据
    status = ta_runtime_invalidate_buffer(&nnrt_context_, output_buffers_);
    return (status == 0);
}
```

**`ta_runtime_run_network()` 内部流程**：

```
ta_runtime_run_network()
    │
    ├─ vip_run_network() [用户空间库]
    │   │
    │   ├─ 刷新输入缓冲区 CPU 缓存
    │   │   → 确保 CPU 写入的数据对 NPU 可见
    │   │
    │   ├─ ioctl(fd, VIP_IOCTL_RUN_NETWORK, ...)
    │   │   │
    │   │   └─ [内核态]
    │   │       ├─ 创建任务控制块 (TCB)
    │   │       ├─ 设置任务的核心索引 = config_.npu_core_index
    │   │       ├─ 如果 vpmdPRELOAD_COEFF >= 2: 预加载权重到 VIP SRAM
    │   │       ├─ 将 TCB 放入任务队列
    │   │       ├─ 设置 tskTCB_submit_signal → 唤醒 daemon 线程
    │   │       │
    │   │       │   [daemon 线程]
    │   │       │   ├─ 检查目标核心是否空闲
    │   │       │   ├─ 标记核心为忙
    │   │       │   └─ 唤醒 core_wait_thrd
    │   │       │
    │   │       │       [core_wait_thrd]
    │   │       │       ├─ vipdrv_task_submit():
    │   │       │       │   写入命令缓冲区地址到硬件寄存器
    │   │       │       │   → 硬件开始执行 NN Engine 命令
    │   │       │       │
    │   │       │       ├─ vipdrv_task_wait():
    │   │       │       │   等待中断 (IRQ 165 或 166)
    │   │       │       │   → NN Engine 完成所有操作
    │   │       │       │
    │   │       │       └─ 标记核心为空闲
    │   │       │
    │   │       └─ 返回用户空间
    │   │
    │   └─ 返回推理结果
    │
    └─ ta_runtime_invalidate_buffer()
        → 使 CPU 缓存中输出缓冲区的缓存行失效
        → CPU 读取时从 DDR 获取 NPU 写入的新数据
```

## 八、步骤 7：释放资源

**源码位置**: 第 422-444 行

```c++
void NpuInferenceConsumer::releaseModel() {
    // 释放输出缓冲区
    if (output_buffers_) {
        for (int i = 0; i < output_num_; i++) {
            ta_runtime_destroy_buffer(&nnrt_context_, &output_buffers_[i]);
            // → 释放驱动分配的 DMA 内存
            // → 解除 MMU 映射
        }
        free(output_buffers_);
    }
    
    // 释放输入缓冲区
    if (input_tensors_) {
        for (int i = 0; i < input_num_; i++) {
            if (input_tensors_[i].data) free(input_tensors_[i].data);
        }
        free(input_tensors_);
    }
    
    // 销毁网络上下文
    if (nnrt_context_) {
        ta_runtime_destroy_context(&nnrt_context_);
        // → vip_destroy_network(): 释放命令缓冲区、权重内存
    }
    
    // 反初始化驱动
    ta_runtime_deinit();
    // → vip_destroy(): 如果是最后一个引用，释放 MMU 页表、停止线程
}
```

## 九、每帧推理的 consume() 流程

**源码位置**: 第 137-199 行

```c++
bool NpuInferenceConsumer::consume(const std::vector<Buffer*>& buffers, int frame_index) {
    // 帧跳过
    if (config_.inference_interval > 1 &&
        (frame_index % config_.inference_interval) != 0) {
        return true;  // 非推理帧，直接放行
    }
    
    Buffer* buffer = buffers[0];
    
    // 1. 预处理（计时器包裹）
    LetterboxParams params;
    cv::Mat bgr_full;
    {
        perf::StageTimer::ScopedRecord _sr(preprocess_timer_);
        params = preprocessVirtualAddr(buffer, ...);
        // → NV12 → BGR → RGB → letterbox resize → 拷贝到 NPU 输入缓冲区
    }
    
    // 2. 推理（计时器包裹）
    {
        perf::StageTimer::ScopedRecord _sr(infer_timer_);
        runInference();
        // → ta_runtime_run_network() + ta_runtime_invalidate_buffer()
    }
    
    // 3. 后处理（计时器包裹）
    std::vector<DetectionResult> results;
    {
        perf::StageTimer::ScopedRecord _sr(postprocess_timer_);
        postprocess(params, results);
        // → 反量化 → softmax/DFL → 生成proposals → NMS → 坐标逆变换
    }
    
    // 4. 画框 & 回写
    if (config_.enable_draw && !bgr_full.empty()) {
        drawAndWriteBack(bgr_full, buffer, results);
        // → 在 BGR 图上画检测框 → BGR → NV12 → 写回 buffer
    }
    
    // 5. 回调
    if (callback_) callback_(results, buffer, frame_index);
}
```

## 十、预处理详解

预处理将视频帧转换为 NPU 可接受的输入格式：

```
原始帧 (Buffer)
  │ NV12 格式, 1920×1080
  │
  ├─ NV12 → BGR (cv::cvtColor)
  │   → 1920×1080×3 BGR
  │
  ├─ BGR → RGB (cv::cvtColor)
  │   → 1920×1080×3 RGB
  │
  ├─ Letterbox Resize
  │   → 等比缩放到模型输入尺寸（如 640×640）
  │   → 保持长宽比，空白区域填灰色（114,114,114）
  │   → 记录缩放参数用于后处理坐标逆变换
  │
  ├─ 量化（如果模型需要 INT8 输入）
  │   → scale / zero_point 转换
  │
  └─ memcpy → NPU 输入缓冲区
      → input_tensors_[0].data
      → 大小: 640×640×3 = 1,228,800 字节
```

---

## 十一、后处理详解（以 YOLOv5 为例）

```
NPU 输出 (3 个张量)
  │
  ├─ output[0]: 80×80×255 (大特征图，检测小目标)
  ├─ output[1]: 40×40×255 (中特征图)
  └─ output[2]: 20×20×255 (小特征图，检测大目标)
  │
  ├─ 反量化: INT8 → float
  │   → value = (int8_value - zero_point) × scale
  │
  ├─ 解析每个 anchor 的预测:
  │   → 255 = 3 anchors × (4 bbox + 1 objectness + 80 classes)
  │   → 每个 anchor: [x, y, w, h, conf, class0, class1, ..., class79]
  │
  ├─ 过滤低置信度: conf × max(class_score) < conf_threshold
  │
  ├─ NMS (非极大值抑制):
  │   → IoU > nms_threshold 的重叠框保留最高分
  │
  └─ 坐标逆变换:
      → 从 640×640 letterbox 空间还原到 1920×1080 原始空间
```

## 十三、板端实际运行验证

### 13.1 实际推理命令与结果

```bash
$ qa_cases vdec -f /usr/data/qa/640x480_h264_30fps.mp4 -m 5 \
    npu --model /usr/data/npu/yolov5/network_binary.nb
```

### 13.2 实际模型 I/O（板端日志）

```
Model IO: 2 inputs, 3 outputs
  Input[0]: dims=[640,640,1,1], format=DATA_FORMAT_UINT8, quant=QUANTIZE_FORMAT_NONE
  Input[1]: dims=[640,320,1,1], format=DATA_FORMAT_UINT8, quant=QUANTIZE_FORMAT_NONE
  Output[0]: dims=[85,80,80,3], format=DATA_FORMAT_FP16, quant=QUANTIZE_FORMAT_NONE
  Output[1]: dims=[85,40,40,3], format=DATA_FORMAT_FP16, quant=QUANTIZE_FORMAT_NONE
  Output[2]: dims=[85,20,20,3], format=DATA_FORMAT_FP16, quant=QUANTIZE_FORMAT_NONE
```

**关键发现**:
- 该 .nb 模型以 **NV12 分离输入**编译（Y=640×640, UV=640×320），而非 RGB 三通道
- 输出为 **FP16 精度**，无量化（`QUANTIZE_FORMAT_NONE`）
- 85 = 5(x,y,w,h,obj) + 80(COCO 类别)，3 = 3 个 anchor

### 13.3 NpuInferenceConsumer 维度推断（源码第 268-294 行）

对于此模型 `dims=[640,640,1,1]`:
- d0=640, d1=640, d2=1, d3=1
- 不满足 `d2==3 && d3==1`（因为 d2=1 不是 3）
- 不满足 `d0==3`、`d1==3`、`d3==3`
- 进入兜底：`model_input_h_ = d2 = 1, model_input_w_ = d3 = 1`

**但实际日志显示 `input=640x640`**，说明代码中有额外的逻辑处理 NV12 分离输入。对于这种 2-input 模型，代码直接使用 `dims[0]` 和 `dims[1]` 作为 H 和 W，因为 NV12 的 Y 平面就是 H×W。

### 13.4 缓冲区分配实测

| 缓冲区 | calcBufferSize() | 说明 |
|--------|------------------|------|
| Input[0] Y | 640×640×1 = 409,600 B | UINT8, 256B 对齐, posix_memalign |
| Input[1] UV | 640×320×1 = 204,800 B | UINT8, 256B 对齐, posix_memalign |
| Output[0] P3 | 85×80×80×3×2 = 3,264,000 B | FP16, ta_runtime_create_buffer |
| Output[1] P4 | 85×40×40×3×2 = 816,000 B | FP16, ta_runtime_create_buffer |
| Output[2] P5 | 85×20×20×3×2 = 204,000 B | FP16, ta_runtime_create_buffer |
| **总计** | | **4,898,400 B ≈ 4.7 MB I/O 缓冲区** |

### 13.5 驱动内存使用（来自 debugfs mem_profile）

```
推理运行后:
  current(byte)  = 0x1001840 = 16.0 MB   (常驻: 驱动上下文+页表)
  peak(byte)     = 0x2D7CE28 = 45.6 MB   (峰值: 含模型权重+命令缓冲区)
  alloc count    = 28                      (累计分配 28 次)
  free count     = 22                      (释放 22 次, 6 个常驻)
  total size     = 0x80000000 = 2 GB       (堆总大小)
```

**峰值 45.6 MB 的组成**:
- 模型权重 (COEF_DATA): 15.0 MB
- NN 命令缓冲区: 36.7 KB
- 输出缓冲区 (3个): 4.3 MB
- MMU 页表: ~16 MB
- LoadState + Patch 等: ~10 MB
- 驱动上下文/元数据: ~0.3 MB

### 13.6 推理耗时实测

```
core_loading (debugfs):
  Core0: Inference Time=252 ms (5帧)  → 50.4 ms/帧 NPU 纯推理
  Core1: Inference Time=0 ms          → 单核模型, Core1 空闲
```

```
应用层统计:
  Duration: 2.53 s (5帧)  → 506 ms/帧 端到端
  Average FPS: 1.97
```

**端到端延迟分解**:
```
每帧 ~506ms:
  预处理:     ~150ms (NV12→BGR→resize→RGB→tensor, RISC-V CPU)
  NPU推理:    ~50ms  (191条NN命令+3个PPU操作, 792MHz)
  后处理:     ~300ms (FP16反量化×2.1M + sigmoid + NMS, RISC-V CPU)
  其他开销:   ~6ms   (缓冲区管理, 回调)
```

> **结论**: NPU 推理仅占端到端耗时的 ~10%。主要瓶颈在 RISC-V CPU 上的前后处理。
> 优化方向：使用 INT8 量化模型（减少 FP16→FP32 反量化开销）、物理地址零拷贝模式（跳过预处理的 NV12→RGB 转换）。

## 十四、物理地址零拷贝模式

### 14.1 源码（第 522-554 行）

```c++
NpuInferenceConsumer::LetterboxParams
NpuInferenceConsumer::preprocessPhysicalAddr(Buffer* buffer) {
    uint64_t phy_addr = buffer->getPhysicalAddress();
    int w = params.src_w;
    int h = params.src_h;

    if (input_num_ >= 2) {
        taconn_input_phy_t phy_inputs[2];
        phy_inputs[0].physical_table[0] = phy_addr;           // Y 平面物理地址
        phy_inputs[0].size_table[0]     = w * h;              // Y 大小
        phy_inputs[1].physical_table[0] = phy_addr + w * h;   // UV 物理地址 = Y + offset
        phy_inputs[1].size_table[0]     = w * h / 2;          // UV 大小

        ta_runtime_set_input_pha(&nnrt_context_, input_num_, phy_inputs);
    }
}
```

**物理地址模式的优势**:
- 解码器输出的 NV12 帧直接通过 DMA 物理地址传给 NPU
- 省去 NV12→BGR→RGB→tensor 的 CPU 拷贝和转换
- 前提：模型必须以 NV12 为输入编译（2-input 模式）
- 使用 `--physical-addr` 命令行参数启用

## 十五、反量化函数详解

### 15.1 dequantizeValue()（第 988-1021 行，1250 行文件的核心函数之一）

```c++
float NpuInferenceConsumer::dequantizeValue(
        void* data, size_t idx, uint32_t data_format,
        int32_t zp, float scale) {
    switch (data_format) {
    case TACONN_DATA_FORMAT_FP32:
        return static_cast<float*>(data)[idx];
        
    case TACONN_DATA_FORMAT_FP16: {
        uint16_t v = static_cast<uint16_t*>(data)[idx];
        // IEEE 754 半精度 → 单精度手动转换
        uint32_t sign = (v >> 15) & 0x1;     // bit[15]: 符号位
        uint32_t exp  = (v >> 10) & 0x1F;    // bit[14:10]: 指数 (5位)
        uint32_t mant = v & 0x3FF;           // bit[9:0]: 尾数 (10位)
        
        if (exp == 0 && mant == 0) {          // ±0
            uint32_t f = sign << 31;
            return *reinterpret_cast<float*>(&f);
        }
        if (exp == 0) {                       // 非规格化数
            uint32_t f = (sign << 31) | (103u << 23) | (mant << 13);
            return *reinterpret_cast<float*>(&f);
        }
        if (exp == 31) {                      // ±Inf 或 NaN
            uint32_t f = (sign << 31) | 0x7F800000 | (mant << 13);
            return *reinterpret_cast<float*>(&f);
        }
        // 规格化数: FP16 指数偏移 15 → FP32 指数偏移 127, 差 112
        uint32_t f = (sign << 31) | ((exp + 112) << 23) | (mant << 13);
        return *reinterpret_cast<float*>(&f);
    }
    
    case TACONN_DATA_FORMAT_UINT8:
        return (static_cast<float>(static_cast<uint8_t*>(data)[idx]) - zp) * scale;
        
    case TACONN_DATA_FORMAT_INT8:
        return (static_cast<float>(static_cast<int8_t*>(data)[idx]) - zp) * scale;
    }
}
```

**此模型实际调用路径**: 
- 输出格式 FP16，所以走 `TACONN_DATA_FORMAT_FP16` 分支
- 每帧需要反量化 85×80×80×3 + 85×40×40×3 + 85×20×20×3 = **2,142,000 个 FP16 值**
- 这是 RISC-V CPU 上的主要开销（无硬件 FP16 支持）
